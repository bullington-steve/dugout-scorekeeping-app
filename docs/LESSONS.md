# Lessons from the first build

Each of these cost real time the first time. Read before working on the related area.

## iPhone and Safari behavior

1. **Home Screen apps keep their own storage**, separate from Safari tabs. Deleting the Home Screen icon deletes that app's data. Re-adding gives an empty app. The first build once told Steve the opposite, which was wrong. Always say: back up, delete, re-add, restore.
2. **Safari can clear a website's data after about a week without a visit** (WebKit's 7-day storage policy). Home Screen apps are exempt. This is why the app pushes people to the Home Screen and to backups.
3. **The icon and its name are snapshotted when added.** A new icon or app name only appears after re-adding (with the backup steps above).
4. **Updates need a full close.** Swiping home doesn't close a Home Screen app. A half-loaded update (part old code, part new) once made taps land in the wrong place for a whole session. After every push, tell Steve to swipe the app away and reopen it, and show the version in Settings.
5. **Page-wide `overscroll-behavior: none` and locking the page (`overflow: hidden` on html while a sheet is open) are suspected of offsetting iPhone taps.** Both were removed. No-bounce is now scoped: an `html.fits` class, only when the screen's content fits, re-checked after render, tab changes, sheets, resize, `document.fonts.ready`, and via a ResizeObserver. Since 2026.11.12-9 it covers every tab (Steve: no bounce on any page that fits), not only the Game screen. If taps ever seem offset on his iPhone, check this first.
6. **After the keyboard closes, iOS can leave fixed bars stuck** a keyboard-height up. Nudge the page to re-layout on keyboard close.
7. **Audio needs a user tap first.** That's why the intro starts with PLAY BALL!. Decode intro audio *before* the tap so it plays instantly.
8. **`navigator.share` with a title plus a file makes iOS offer "Save as 2 Items"** with no file name. Share the file alone.
9. **Wake Lock is ignored by Home Screen apps before iOS 18.4.** A tiny silent looping video keeps the screen on as a fallback.
10. **iPhone Safari won't lock rotation** for websites or Home Screen apps. Design a sideways layout instead.
11. **The ring/silent switch** on older iPads mutes Safari audio.
12. **Usable height** for a Home Screen app on iPhone 16 is about 393 x 759, not 852: the status bar and home indicator take about 93 points. Test at the real usable height.
13. **iOS 26 Safari moved Share** behind the ≡ menu in the address bar; iPad has Share at the top right and "View More" before Add to Home Screen. "Open as Web App" must stay on.
14. **Tinted/dark Home Screen icon styles** recolor icons; a silver icon may look gray in screenshots.

## Rendering and layout

15. **Re-rendering a whole panel on every input** swallowed the first tap on Play Ball, lost focus between text boxes, and wiped half-typed values. Save text input quietly without redrawing the panel.
16. **Rebuilding a list under the finger** (the Organ pad rebuilt itself on each tap and when a tune ended) made taps hit the wrong row on iPhone. Update the changed element in place.
17. **Class name collisions** broke layout twice: the scoreboard's `.empty` cells picked up the "No game in progress" panel's styles, and a generic `.play` rule hit the intro states. Namespace classes per component.
18. **Fonts render slightly wider on GitHub's runners** than locally. A Game screen that fit by 9 points locally failed in CI. Keep **at least 12 points of headroom** and keep new button labels no longer than existing ones. It happened again in the rebuild (Nov 2026): STRIKE beside the bases overflowed by 1 point at 260 wide on GitHub only. The 260-point test now also requires every board label to stay 4 points inside the board's edge.
19. **Measure after fonts load.** Fit checks that ran before web fonts finished gave false results.
20. **When a control grows to 44 points, check its container.** The + (add inning) button grew but its column stayed 30 px and collided with R.
21. **Floating close buttons** that follow scrolling ended up over a remove button. Keep ✕ fixed beside the title.
22. **Tap outside to dismiss** threw away a half-built lineup. Sheets close only via ✕, Cancel, or Done.
23. **Pinned table columns** leaked slivers through 1 px seams; use a border model that leaves no gaps.
24. **Wide display fonts** (Graduate, then Alfa Slab One) pushed header icons to a second line on small phones; cap the wordmark by its container's width, and make sure sideways rules aren't overridden by later upright rules.
25. **Taps on the full-screen field** must clamp to the field; converting screen to field coordinates needs a small tolerance in tests.
26. **Kalam's digit 1 reads as a capital I** ("F11" looked like "FII"). Play codes must be readable at a glance; test F11 and 6-3.
27. **Every lit bulb with its own glow filter, plus animated filters, is expensive.** Draw one soft glow behind each bulb and animate only opacity.
28. **Contrast checks can't see what scrolls under glass.** Test the tab bar by mixing its tint over white, black, and paper.

57. **`hidden` loses to `display`.** An element with a `display` rule ignores the `hidden` attribute, so an empty error banner showed as a red stripe. Every component that sets `display` also needs `[hidden] { display: none; }`. It bit again: `.sk-key` sets `display`, so **Restore from Backup** never hid once a team existed, until `.sk-key[hidden]` was added for every key. A test should check a button disappears, not just that it appears.
58. **A file picker must sit inside its button.** The invisible `<input type="file">` covering its button was a sibling instead of a child and covered the whole sheet, eating taps on Done.
60. **A covering file picker must cover the border too.** Inset 0 left the picker 40 points tall inside a 44-point button (the button's border and thicker bottom edge sat outside it), and the 44-point check failed. `.sk-file` now overhangs the border.
61. **Hidden VoiceOver labels can widen the page.** A visually hidden span is `position: absolute`; inside a scrolling table box that isn't positioned, it escapes to the page and makes the whole page scroll sideways (the Batting table's "(team leader)" labels made Stats 914 points wide). Every box that scrolls sideways gets `position: relative`.
62. **WebKit counts a menu's longest choice as overflow inside a grid.** A `<select>` with long choices in a CSS grid (even `minmax(0, 1fr)`) made the page scroll sideways in WebKit only, though every box measured inside the screen. `.sk-field` is now plain block layout, and the Stats header stacks its menu above its buttons. Test sideways scroll in WebKit, not just Chromium.
63. **Long names need somewhere to wrap.** Inline buttons placed next to each other with no space between them can't wrap, so three tied leaders pushed past 260 points. Put such lists in a wrapping flex row.
64. **GitHub's machines have different fonts.** A five-part switch with no-wrap labels fit 260 points here and stuck out 4 points on GitHub's runner. Don't make a fit depend on a font's exact width: let rows wrap at narrow widths, and check fits with letter-spacing pushed wider.
65. **Don't let CI depend on Ubuntu's download mirror.** On Nov 11, 2026, `azure.archive.ubuntu.com` stopped resolving on GitHub's runners for hours, and `playwright install-deps` timed out on every try, so nothing could publish. The browser tests now run inside Playwright's own image (`mcr.microsoft.com/playwright:vX.Y.Z-noble`), which already has the browsers and their libraries. When `@playwright/test` is updated in `package.json`, update the image tag in the workflow to the same version.
66. **Text fields save on "change" too, not just "input."** Two browser tests that type a value and tap **Done** right away each failed once under load with the value missing, and iPhone AutoFill can send only a change event. `textField` now listens for both.
67. **Don't redraw a list while someone might be tapping it.** Dues redrew every name row on each change to the fee. With the keyboard up, tapping a name ends editing (a change event), the rows were replaced mid-tap, and the tap was lost (seen in WebKit tests). Rows now update their text in place and only rebuild when the roster changes.
68. **Measure a scanned line's weight after tracing, not before.** Twice the ink area over its edge length, taken on a raw 300 dpi scan, read his pen as thinner than it is (rough scan edges add length), so the new letters came out 30–45% heavier than his first font. The build now traces each piece, measures the smooth outline the same way it measures the font, and tries widths until they match. Widening also fills the small gaps between close letters in whole words, so it has to be tried, not calculated.
69. **Saved copies must ignore "Vary."** The offline copy had every file, yet the app came up blank with no signal: the preview server marks files "Vary: Origin", and the app's scripts are requested with an Origin header, so `caches.match` never matched. The service worker matches with `ignoreVary: true`. Test offline for real: open once, cut the network, reload.
70. **In tests, type into a sheet only after it has focused its title.** A sheet moves focus to its title on the next frame (for VoiceOver). In WebKit, a test's typing could land in that gap and vanish, which looked like Dues losing the fee or an amount (LESSONS 66 guessed wrong at the cause). Wait for the title to be focused, then type. Someone tapping on an iPhone can't hit this.
71. **The welcome screen is only for a truly new device.** Data that was set aside, or saved by a newer app, also leaves the app "empty"; showing the welcome there hid the warning that explains what happened. First launch checks that nothing was saved at all.
72. **A fake server in tests must answer the browser's preflight.** WebKit asks a cross-site server first (an OPTIONS request) before posting JSON; a test's fake Discord that only answered the POST looked like "couldn't reach Discord." Real Discord answers it. Fakes answer OPTIONS with the CORS headers too.
73. **Tests that fake a server can't have the offline copy running in WebKit.** Once the service worker controls a page, Playwright's WebKit stops seeing that page's outgoing requests, so its fakes never fire. Those test files use `test.use({ serviceWorkers: 'block' })`; the offline test keeps it on.
74. **Check every screen at the largest text, not just the Game screen.** At Larger Text's maximum (about 312%), anything that can't wrap runs off the side: a button label with no `max-width`, an absolutely placed pill, a three-column strip with fixed columns, a name with no `overflow-wrap`. `.sk-key` now has `max-width: 100%`; rows that share space use flex-wrap with a basis in `em`, so they stack only when the text is big. `tests/e2e/parity.spec.ts` holds it.
75. **Under Reduce Motion, turn transitions off; don't shorten them.** `transition-duration: 0.01ms` on every element makes every property transition (the property defaults to `all`), including ones that never had a transition, so a new color shows a frame late. It looked like flaky contrast on the tab bar. `transition: none` is right.
76. **Safari has no vibration call, but a switch flip is felt.** `navigator.vibrate` doesn't exist on iPhone. Since iOS 18, toggling an `<input type="checkbox" switch>` (here by clicking its label) plays the system haptic tick, and it follows the iPhone's System Haptics setting. Only confirmable on a real iPhone.
77. **VoiceOver-only controls are skipped by the tap and contrast checks.** The Organ's tune list is visually hidden (1 × 1 points) so VoiceOver can use it while the wheel is for eyes and thumbs. The checks skip anything inside `.sk-visually-hidden`; tests activate those buttons with `element.click()` the way VoiceOver does, not a pointer tap.
78. **A home run out is only possible over the limit, and goes over the fence.** The sample data showed HROs before a team's second home run and as balls "fielded by" someone. Over-the-fence home runs and HROs land past the fence, in the air, with no fielder; inside-the-park home runs land short of it. The hand scorer only draws HRO once the team is over its limit, and deep balls go to the true outfielders, never the short fielder.
79. **Changing the hand scorer's draws changes every seed.** Adding or removing one choice from its random list shifts every later draw, so the permanent seeds no longer cover the same rules. After any change, rerun the coverage test and add seeds that cover what went missing (a quick loop over seeds 1–400 finds them).
80. **Safari ignores `user-scalable=no`.** Since iOS 10, Safari pinch-zooms anyway. To keep the screen still (Steve, Nov 12), the app also cancels Safari's `gesturestart` / `gesturechange` / `gestureend` events and sets `touch-action: pan-x pan-y` on everything (no pinch, no double-tap zoom); controls that follow a finger keep `touch-action: none`. Dynamic Type and iOS's own Zoom are untouched. Only confirmable on a real iPhone.
81. **A fit test must cover the fullest version of the screen.** The Game screen's fit test started a fresh game, so the batter never had earlier at-bats, and the new at-bat boxes would have overflowed unseen. It now bats around until the batter has three boxes.
82. **Safe areas counted twice made the Game screen scroll on a real iPhone.** The body pads for the Dynamic Island and Home indicator, and `.sk-app` was also `min-height: 100dvh`, so the page was the whole screen plus about 93 points, and it scrolled the header up under the status bar (Steve's screenshot, Nov 12). The headless browsers have no safe areas, so every fit test passed. Now the safe areas are `--safe-top` / `--safe-bottom` variables, `.sk-app` fills only what's left, and a fit test stands in for a real iPhone 16 (393 × 852 with 59 and 34) by setting those variables.
